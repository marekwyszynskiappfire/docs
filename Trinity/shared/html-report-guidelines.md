# Shareable HTML report guidelines

Canonical rules for **The Reviewer**, **The Creator**, and any future agent-built HTML reports in this repo. Reference implementation: [`Creator/runs/TC-6504/report/`](../Creator/runs/TC-6504/report/).

---

## Goals

1. **Portable** — zip a folder or commit to git; recipients open `index.html` without a server, login, or repo checkout.
2. **Safe** — no CDN dependencies; safe on `file://`; no secrets or signed URLs in artifacts.
3. **Accessible** — keyboard, screen readers, visible focus, meaningful labels.
4. **Maintainable** — data generated by scripts; prose/layout rules in skills; avoid hand-editing rendered output.

---

## Report profiles

| Profile | Use when | Layout | Filters |
|---------|----------|--------|---------|
| **A — Document** | Narrative review, test suite catalog, readiness handoff | Single self-contained `.html` **or** portable folder with one HTML + inline CSS | Optional light JS (e.g. decision export). Tiering via native `<details>`. |
| **B — Interactive facet** | Tables, triage, analytics over many rows | **Portable folder** (required): `index.html`, `assets/styles.css`, `assets/app.js`, generated `data/report-data.js` | **Combinable AND filters**; facet counts **update** when selection changes (faceted search). |

**The Reviewer** per-epic `review-report.html` is **Profile A** (renderer: `The Reviewer/scripts/render_report.py`, tier spec in `The Reviewer/reference.md`).

**The Reviewer** multi-Epic **`portfolio/`** bundle (≥2 epics in one run) is **Profile B** (builder: `The Reviewer/scripts/build_portfolio_report.py`, template: `The Reviewer/portfolio-report-template/`). Open `portfolio/index.html`; zip the whole `portfolio/` folder to share. Epic report links inside the portfolio use **relative** paths (`epics/{KEY}/review-report.html`). **Creator handoff:** toggles + exported `creator-handoff.json` (JQL + Jira search URL) for downstream test generation.

**Creator execution / bug / triage reports** (e.g. TC-6504) are **Profile B** unless explicitly documented otherwise.

**Test suite HTML** (Creator `test-suite-report.html`) is **Profile A** today; new interactive triage UIs must use **Profile B**.

## Portable folder layout (Profile B)

```
report/                    # or share-pack/ — name per run README
  index.html               # shell only; relative asset paths
  README.md                # how to open, regenerate, share
  assets/
    styles.css
    app.js
  data/
    report-data.js         # generated: window.REPORT_DATA = …
```

**Build script** (e.g. `build_*_report.py`) lives **outside** `report/` in the run folder; it writes only `data/report-data.js` (and optional JSON export). Static HTML/CSS/JS are source-controlled in `report/assets/`.

**Do not** require `fetch()` of JSON on `file://` — embed data via `report-data.js` or `<script type="application/json">` parsed in JS.

## Profile B — filter behaviour (required)

1. **Multiple active filters** combine with **AND** (e.g. “bugs this year” + “not automated”).
2. **Facet cards** are toggles (`aria-pressed`); click again to remove one filter.
3. **Clear all** control when any filter is active.
4. **Dynamic counts** on each facet: for facet `F`, count rows that match **all currently active filters except F** and also satisfy `F` (standard faceted search). Stat tiles show aggregates for **visible rows only**.
5. **Text search** ANDs with facet filters.
6. **URL hash** (optional): `#f=id1,id2` for shareable state; wrap `history.replaceState` and `decodeURIComponent` in try/catch for `file://`.

## Security and embedding data

When embedding JSON in `.js`:

- Use `json.dumps(..., ensure_ascii=True)` and escape `</` as `<\/` in script bodies.
- Never embed raw HTML from Jira into JS string literals without escaping.
- Apply **redaction** before data reaches any report file (same rules as Reviewer `reference.md`).

No external scripts, fonts, or CSS from CDNs.

---

## Accessibility and UX (both profiles)

- `lang="en"` on `<html>`; one logical `<h1>`.
- Skip link to main table/content where the page is long.
- `:focus-visible` on interactive controls; don’t rely on colour alone.
- Sortable tables: header buttons or `th` with `aria-sort` when sorted.
- Live region for result counts when filters change (`aria-live="polite"`).
- Respect `prefers-reduced-motion`.

## Document report rules (Profile A)

- **The Reviewer:** payload → `render_report.py --strict`; never hand-write `review-report.html` / `.md`. Section order and tiers: `reference.md` § HTML report.
- **Creator test suite:** self-contained single file; inline CSS; `<details>` per test; full step bodies inside details (not title-only). See test-case-creation skill §9b.
- Inline CSS only unless using Profile B split assets.
- Reports must remain readable with JavaScript disabled (Reviewer tiering uses `<details>` without JS).

## Run folder conventions

| Tool | Artifacts | Shareable bundle |
|------|-----------|------------------|
| The Reviewer (single issue) | `{artifacts_dir}/{run_id}/{KEY}/review-payload.json` + rendered reports | Copy `review-report.html` (+ optional `.md`) — single file share |
| The Reviewer (≥2 Epics, one run) | `{portfolio_run_id}/{KEY}/…` + **`{portfolio_run_id}/portfolio/`** | Zip **`portfolio/`** — `index.html` + `epics/{KEY}/review-report.html` |
| The Creator (runs) | `Creator/runs/{RUN_ID}/` batches + build scripts | **`Creator/runs/{RUN_ID}/report/`** zip |
| AI in QA / TestCaseCreator | `artifacts/{KEY}/` | Suite HTML per skill paths; follow Profile A until migrated |

Each shareable folder includes a **README.md** with: open instructions, regenerate command, data freshness note.

---

## Agent checklist (before delivering HTML)

- [ ] Profile A or B chosen and matches skill for this artifact type
- [ ] Profile B: folder layout, split CSS/JS, generated `report-data.js` only from build
- [ ] Profile B: combinable AND filters + dynamic facet counts + clear-all
- [ ] No CDN; works on `file://` (test or document constraint)
- [ ] Redaction applied to embedded text
- [ ] Safe JSON embedding if using `report-data.js`
- [ ] README in share folder; user told path to zip or open `index.html`
- [ ] Reviewer: rendered via `render_report.py`, not hand-written HTML
