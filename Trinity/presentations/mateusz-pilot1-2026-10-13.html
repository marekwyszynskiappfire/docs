Trinity

AI-assisted test case generation with human control

POC closure · 13 Oct 2026 · Marek Wyszyński

Release 0.2.0 · trinity-v0.2.0

Problem

  • Manual test design from Jira requirements is slow and inconsistent.
  • Stakeholders need useful AI output — not a demo-only generator.
  • Evidence: acceptance rate, human review, prod Xray traceability.

Solution — one pipeline

  • Reviewer — structured requirements review
  • Creator — test cases (golden style, coverage catalog)
  • Studio — approve / reject with reason enum
  • Importer — validated handoff → Xray on Jira PROD (TC project)

Docs: Confluence QACoE · git Trinity/FIRST-RUN.md

Does it work? Yes

Pilot 1 — ONE-228469 (production import)

  • 5 tests created in Xray: TC-6704 … TC-6708
  • Dedicated test project (TC); prod-only write policy

Scorecard: Trinity/SCORECARD.md

How we control quality

  • Reviewer findings and readiness before Creator
  • Human review in Studio (approve / reject + reasons)
  • Importer validation before Xray create
  • Granularity: golden corpus + personas + Studio edits
